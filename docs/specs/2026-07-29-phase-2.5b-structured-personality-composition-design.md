# Phase 2.5b — Structured Personality Composition

> **Status:** Design approved (adversarial review completed 2026-07-29, 6 rounds)
> **Branch:** `feat/wacky-manor-poc` (casehubio/examples)
> **Depends on:** eidos#107 (landed on upstream/main), eidos#123 (YAML registrar — proposed), Phase 2.5 (validated)

## Goal

Validate that structured personality frameworks (Jungian cognitive functions, Belbin team roles) produce measurably different autonomous character behavior compared to flat string dispositions. Run an incremental composition experiment — each layer adds one framework and measures its contribution — to produce evidence that composition actually does something.

## Eidos Change (proposed — eidos#123)

Extend `ClasspathYamlDescriptorRegistrar.DispositionConfig` to support two new optional YAML fields:

- `mbtiType` (String) — convenience shorthand (e.g. `ENTJ`).
- `dispositionProfile` (list of `{term, weight}`) — direct weighted profile for cases that don't map to a standard MBTI type.

**Resolution path (preserving module boundaries):** The registrar resolves `mbtiType` through `VocabularyRegistry.resolve("urn:casehub:vocab:mbti", mbtiTypeValue.toLowerCase(Locale.ROOT))`, which returns `Optional<VocabularyTerm>`. The lowercase normalization is required because `MbtiTypeTerm.value()` returns lowercase strings (e.g. `"entj"`) while YAML convention uses uppercase (e.g. `ENTJ`). `CdiVocabularyRegistry.resolve()` does case-sensitive `Map.get(value)` lookup — without normalization, the resolve silently returns `Optional.empty()` and the descriptor gets no disposition profile. The `mbtiType` field is case-insensitive in YAML; the registrar normalizes before resolution.

A new default method `defaultProfile()` on `VocabularyTerm` (in `casehub-eidos-api`) returns `List<DispositionValue>` — empty by default, overridden by `MbtiTypeTerm`. This follows the existing pattern of `specializes()`, `axisExactMatch()`, `impliesSupervision()`, and `opposite()` — all default methods on the API interface overridden by specific vocab terms. The registrar never references `casehub-eidos-vocab` types directly.

If `mbtiType` is set, it generates the `dispositionProfile` automatically via this vocabulary-registry path. If both are set, explicit profile wins. The `toDescriptor()` method wires these into `AgentDisposition.builder().dispositionProfile(...)`.

**Prerequisite:** `dispositionVocabulary` (or `domainVocabulary`) must be set in the YAML for disposition axis auto-derivation to fire. `DescriptorCollector.deriveDispositionAxes` checks for a registered vocabulary URI — if absent or unregistered, it returns the descriptor with the raw profile but no derived axes (socialOrient, ruleFollowing, etc. remain empty). For Jungian profiles, always set `dispositionVocabulary: urn:casehub:vocab:jungian`.

The `dispositionVocabulary` field already parses from YAML. No breaking changes.

**Status:** This change is NOT yet on main. Commit `a32b1c1` (eidos#111) added `dispositionProfile` to `AgentDisposition` (API) and updated the registrar to use the builder pattern, but did not add `mbtiType`/`dispositionProfile` to `DispositionConfig`. Filed as eidos#123 — blocker for the examples work.

## Descriptor Changes (wacky-manor)

Replace flat string dispositions with Jungian profiles. The `dispositionVocabulary` is set to `urn:casehub:vocab:jungian`. Existing flat axis fields are removed — `DescriptorCollector` auto-derives all 5 axes from the Jungian function weights via cross-vocabulary projection (Jungian → Conscientiousness for axes 1–4, Jungian → Thomas-Kilmann for conflictMode).

**Mechanism of influence:** Belbin currently has no `axisExactMatch` implementation (eidos#121), so it does NOT feed into the disposition axis derivation system. The behavioral signal channel is prompt rendering: when `slotVocabulary: urn:casehub:vocab:belbin` is set, `EidosRenderPipeline` resolves the slot value via `VocabularyRegistry` to obtain `BelbinTerm.label()` and `BelbinTerm.description()`. These appear in the system prompt as `slotLabel`, `slotDescription`, and `slotVocabularyName`, which the LLM enrichment step weaves into the disposition narrative. For example, a character with `slot: shaper` renders as "Shaper — Challenges the team to improve; driven, dynamic, thrives under pressure" in the system prompt context, giving the LLM a team-role frame beyond the cognitive function profile.

## Test Methodology

Four layers in a 2×2 factorial design (Jungian × Belbin), run sequentially. Same autonomous scenario each time (tea-poisoning, max 180 turns, verdict: POISONED or TURN_LIMIT). Three runs per layer configuration at fixed temperature (0.7) and deterministic seed to control for LLM output stochasticity.

### Layers

**Layer 0 — Baseline (no Jungian, no Belbin):** Flat string dispositions, no vocabulary grounding. Run scenario, capture transcript. This is the control.

**Layer 1 — Jungian only (Jungian, no Belbin):** Replace flat dispositions with `mbtiType` profiles. `dispositionVocabulary: urn:casehub:vocab:jungian`. Axes auto-derived. Run scenario, capture transcript.

**Layer 2 — Belbin only (no Jungian, Belbin):** Flat string dispositions retained, but add `slotVocabulary: urn:casehub:vocab:belbin` with Belbin role assignments. This isolates Belbin's prompt-rendering contribution (slot label and description in the system prompt) without Jungian disposition axis derivation.

**Layer 3 — Jungian + Belbin composite (Jungian, Belbin):** Full composite — Jungian `mbtiType` profiles with `slotVocabulary: urn:casehub:vocab:belbin` and Belbin role assignments. This is the target state.

### Profile Switching

A `manor.scenario.profile` config property selects which descriptor variant to load: `baseline`, `jungian`, `belbin`, `composite`. This avoids editing YAML between runs. The `ScenarioMode` property (`scripted`/`autonomous`) remains orthogonal.

**Implementation:** Four separate YAML descriptor files under `META-INF/eidos/`:

- `descriptors-baseline.yaml` — flat string dispositions, `slot: manor-character` (current descriptors, renamed)
- `descriptors-jungian.yaml` — `mbtiType` + `dispositionVocabulary: urn:casehub:vocab:jungian`, `slot: manor-character`
- `descriptors-belbin.yaml` — flat dispositions, `slotVocabulary: urn:casehub:vocab:belbin`, `slot: <belbin-role>`
- `descriptors-composite.yaml` — `mbtiType` + Jungian disposition + Belbin slot vocabulary

A `ProfileAwareDescriptorRegistrar` replaces the default `ClasspathYamlDescriptorRegistrar` scan path. It reads `manor.scenario.profile` and loads only the matching file. This avoids `FAIL_ON_UNKNOWN_PROPERTIES = true` failures when a YAML file contains fields (e.g. `mbtiType`) that the pre-change registrar cannot parse.

### Evaluation

**Qualitative (primary — autonomous gameplay):** Read transcripts per layer. Are characters more differentiated? Does cognitive style visibly influence decision-making? Does Belbin role change group interactions? This is the primary evaluation method for the autonomous scenario — the judges below do not score gameplay transcripts.

**Quantitative — prompt quality verification** (eidos-eval judges, `casehub-eidos-eval` eidos#113/#117 — add as test-scoped dependency):

- `MbtiAlignmentJudge.evaluate(systemPrompt, expectedType)` — verifies that the **rendered system prompt** presents as the declared MBTI type. Takes a rendered prompt and an expected type (e.g. `"ENTJ"`); sends the prompt to an LLM judge with 12 MBTI personality questions; scores alignment across 4 dimensions (EI, SN, TF, JP). This is a prompt quality precondition — if Layer 1's rendered prompt doesn't present as ENTJ, behavioral differences can't be attributed to the Jungian framework. Run once per profile per layer (results are deterministic per rendered prompt, so multiple runs with the same prompt are redundant).

- `FunctionActivationJudge.evaluate(systemPrompt, agentType, scenarios)` — verifies that agents activate expected cognitive functions under **controlled test scenarios**. Takes a rendered system prompt, agent type, and a list of `FunctionScenario` instances, each with a `targetFunction` and a scenario prompt. The agent responds to each scenario; a judge LLM identifies which cognitive function was activated. Requires designing manor-themed scenarios (e.g., "You discover a hidden passage behind a bookcase" → target: `se` for ESTP; "Two characters are arguing over the treasure map" → target: `fe` for ESFJ). These scenarios are separate from the autonomous gameplay — they test the mechanism in controlled conditions.

**Not in scope for this phase:** A transcript-scoring judge that evaluates behavioral personality expression during autonomous gameplay. The qualitative evaluation fills this role. Quantitative behavioral scoring from transcripts is deferred to follow-on work (eidos#122).

### Experimental Controls

- **Runs per layer:** 3 runs per configuration (12 runs total across 4 layers).
- **Temperature:** Fixed at 0.7 across all runs.
- **Seed:** Deterministic seed per run number (same seed sequence across layers) to reduce stochastic variation.
- **Scenario invariant:** Same autonomous tea-poisoning scenario, same max turns (180), same character set.
- **Held constant across layers:** Briefing text, template references, capabilities, goals, and constraints are identical in all four descriptor variants. Only disposition fields, vocabulary URIs, and slot assignments change. This is essential — briefing text carries rich behavioral instructions (speech patterns, character voice, specific reactions) that likely dominate LLM behavior. The experiment tests whether structured personality frameworks add measurable signal on top of detailed character descriptions, which is the realistic use case.
- **Null result interpretation:** If no layer differences emerge, the cause is ambiguous: structured frameworks may be ineffective, or their signal may be masked by dominant briefing text. Distinguishing these interpretations would require a separate experiment with minimal briefings — out of scope for this phase.
- **Comparability:** Evaluate all 12 transcripts with the same qualitative criteria; run prompt quality checks (`MbtiAlignmentJudge`) and function activation checks (`FunctionActivationJudge`) once per profile per layer. Layer differences in qualitative evaluation are meaningful only if they exceed within-layer variation.

### Verdict Gates

- Layer 1 vs 0: Did Jungian profiles change behavior measurably? If no → profiles aren't reaching the LLM effectively.
- Layer 2 vs 0: Did Belbin slot labeling alone change behavior? If no → prompt-rendered role labels are insufficient signal.
- Layer 3 vs 1: Did Belbin add observable signal beyond Jungian? Is the composite coherent — do the frameworks reinforce or contradict?
- Layer 3 vs 2: Did Jungian add observable signal beyond Belbin? Confirms disposition axis derivation contributes independently.

## DISC Exclusion

DISC is excluded from the experiment. The `personality-frameworks.md` compatibility table marks `Jungian + DISC = Redundant` — Jungian's 8 cognitive functions strictly subsume DISC's 4 behavioral quadrants. Both describe behavioral style, but Jungian is deeper (8 functions with structural rules vs. 4 quadrants); using both creates contradictory disposition encodings because Jungian projects onto the same Conscientiousness axes as DISC via `axisExactMatch`. Thomas-Kilmann is implicit in every Jungian step (functions auto-derive `conflictMode` via cross-vocabulary projection).

## Follow-on Work (not in scope)

- **eidos#122:** Vocabulary imbue-and-verify test suite in eidos-eval — isolated per-vocabulary and pairwise composition tests proving each framework works independently when an LLM is imbued with it.
- **eidos#121:** Belbin `axisExactMatch` mappings — the compatibility doc notes implied disposition values per role but `BelbinTerm` has no `axisExactMatch` implementation. When implemented, Belbin roles would feed into disposition axis derivation in addition to the prompt-rendering channel.
- **Paper potential:** The 4-layer experiment with quantitative eval scores could contribute toward publishable evidence on structured personality composition in LLM agents. Reaching publication quality would require additional rigor: larger sample sizes, inter-rater reliability for qualitative evaluation, formal effect size criteria, and evaluator blinding — all beyond this phase's scope.
